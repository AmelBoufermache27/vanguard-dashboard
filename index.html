What the AI RA needs before coding

Must receive from Engineering
  • One normal run + two fault runs
  • Data dictionary: meaning, unit, sample rate
  • Run identifiers and fault start/end times
  • Clean export script + versioned Simulink model
  • Defined train/test separation by run, not random neighbouring rows
AI deliverables and checks
  • Plot channels, check missingness, avoid leakage
  • Train simple labelled anomaly baseline first
  • Report detection recall, precision and false alarms
  • Evaluate latency/model size only after baseline works
  • Document limitations; create student notebook
Scope distinction: The application also describes TinyML / Edge AI, fail-safe navigation and local small-language-model (SLM) command/report teaching. They are part of the wider curriculum ambition. A single AI RA should prioritise a working anomaly-detection dataset and notebook; confirm when and by whom SLM / navigation tasks are delivered.

Five-step AI development workflow

RECOMMENDED WORK PLAN
STEP 01
Define the data contract

Agree channels, units, run IDs, sampling, fault windows and labels with Engineering RA 2.

STEP 02
Inspect & clean

EDA, missingness plots, normal-vs-fault comparisons, leakage checks and versioned preprocessing.

STEP 03
Start simple

Detect missing/stale values by rules; build a separate sensor-drift baseline with valid reference signals.

STEP 04
Validate across runs

Hold out complete simulation runs. Record precision, recall, false alarms and detection delay.

STEP 05
Package for teaching

Provide rerunnable notebooks; assess TinyML and agree L6 local SLM teaching activity with the PI.
